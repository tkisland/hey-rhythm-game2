# POJI POJI GOの開始位置が変わらない場合の切り分け

報告されたページは `https://tkisland.github.io/hey-rhythm-game2/game.html?song=poji-poji-go`。収録版のMIDI基準を3.3秒から3.92秒へ変更した後もノーツが早いとの報告があります。申告された補正はノーツ位置−15ms、入力0msです。

収録版はMIDIの0tickが動画3.92秒、冒頭2拍後の最初のノーツが4.535384秒です。変更したコミットのPages配信は成功しています。ただし、この調査環境から公開ページ・配信アーティファクトの取得が制限されており、報告ブラウザで実際に使われた譜面は未確認です。

公開プレイは `publishedChart()` が取得したオンライン公開譜面を収録版より優先します。これは管理者公開の既存仕様です。オンライン版の時刻が以前のままなら、収録JSONだけを変更しても表示は変わりません。現在、その条件に該当すると断定できる実ブラウザの記録はありません。

## 確認手順

1. ゲームURLに `&sync=1` を追加し、配信版ID・使用中の譜面・拍の基準（収録MIDIでは0tick）・最初のノーツ時刻・収録版の時刻を確認します。
2. 「収録譜面だけで比較する」で `sync=1&bundled=1` の比較モードへ切り替えます。オンライン譜面の取得を省き、同じ配信に含まれる収録JSONを使います。診断を折りたたんでゲームスタートしてください。
3. 「通常の譜面に戻す」でオンライン優先へ戻れます。比較モードでFirebaseや保存済み補正値を書き換えることはありません。比較中はランキング登録・結果共有を行いません。
4. 「診断ログを保存」には `buildId`、ページのorigin/path、`charts`（取得元・改訂・難易度・基準時刻・最初/最後のノーツ・保存件数/判定件数）が入り、従来のAPI時刻・補間時刻・補正値と突き合わせられます。ログはローカル保存のみです。

`bundled=1` だけでは通常の取得元を変えません。管理者の下書きプレビュー認証や未公開難易度の制限は維持します。

使用中の最初のノーツが3.915384秒・収録版が4.535384秒なら、オンライン版の優先により差分が反映されていないと判断できます。両方の最初のノーツが4.535384秒で比較中もずれるなら、譜面選択以外の原因をAPI時刻・映像/音声出力・入力記録から調べます。配信版IDが古い場合は、再読み込みと閲覧URLを先に確認します。診断情報を得るまでは、さらに開始位置を動かして埋め合わせません。
