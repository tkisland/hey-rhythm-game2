# 箱オシ音の初回負荷

箱オシが成功した入力処理内で、事前準備が終わっていないと6音の合成が同期的に走っていました。これを、同じ波形を保存した48kHz・32bit floatのWAVへ変更します。WAVはビルド時にJavaScriptへ内包し、モジュール読み込み時にデコードします。入力時の取得待ちや音の合成・デコードはありません。音の長さ、音程、音量、6音が立ち上がる間隔は維持します。

初回入力ではAudioBufferのコピーが1回あり、以降は再利用します。事前処理はAudioContextを作成せず音も鳴らさないため、既存のユーザー操作による音声起動はそのままです。使われていない各音の箱オシ用波形を待機中に合成する処理も外します。

音を変更した場合は、次のコマンドでWAVを再生成してください。単体テストで元の合成関数との完全一致を確認します。

```sh
node scripts/generate-box-sweep.mjs
```

入力時のCPU負荷の計測は、管理者用Viteサーバーを起動し、別のターミナルで行います。

```sh
npm run dev:admin
node scripts/profile-box-sound.mjs http://127.0.0.1:5173
```

待機中の準備を意図的に止め、初回と2回目の `playBoxSweep()` の処理時間を通常速度とCPU 6倍スローダウンで記録します。変更前は初回約16ms／85ms、変更後は約1ms／5msでした。同じ環境での一例であり、物理的な音声出力の遅延や実端末での改善量を保証する数値ではありません。

ブラウザテストでは初回・2回目とも入力処理中にsin・exp・デコードが呼ばれず、音が追加の待ち時間なく1回ずつスケジュールされ、2回目にAudioBufferを再作成しないことを確認します。ゲームの箱オシ操作・採点・完了タイミングは変更しません。
